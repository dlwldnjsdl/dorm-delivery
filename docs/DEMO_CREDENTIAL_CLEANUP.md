# 테스트 계정 정보 제거 및 비밀번호 변경 절차

## 이번 변경

- src/main/resources/static/chat-test.html 및 중복 리소스 chat-test.html을 제거했습니다.
- /chat-test.html은 개발/배포 환경 모두 404로 차단합니다. URL 인코딩된 경로도 검사합니다.
- 증분 빌드에서 오래된 리소스가 남아도 최종 JAR에는 포함되지 않도록 패키징에서 제외합니다.
- 일반 React 화면과 API, WebSocket, Push 경로는 유지합니다.
- 실행 중인 예전 서버는 자동으로 바뀌지 않습니다. 새 빌드를 배포하고 서버를 재시작해야 합니다.

## 실제 계정 비밀번호 변경 (아직 실행하지 않음)

현재 사용자 데이터는 변경하지 않았습니다. 노출된 비밀번호는 실제 로컬 계정과 일치했으므로 계정 소유자가 새 비밀번호로 변경해야 합니다. 서비스 계정의 비밀번호와 MySQL 접속 비밀번호는 서로 다릅니다. 이번 조치는 users.password 대상이며 MySQL root 비밀번호를 바꾸라는 뜻이 아닙니다.

가장 간단한 방법은 서버를 외부에 공개하지 않은 상태에서 로컬 React의 비밀번호 재설정 기능을 사용하는 것입니다. 소유자가 본인 정보를 입력해 변경하면 서버 PasswordEncoder가 BCrypt 해시를 저장합니다. 새 비밀번호를 코드·명령행·Git·로그에 넣지 마세요. 이번 작업에서는 재설정 API를 호출하지 않았습니다.

현재 재설정은 이름/전화번호/기숙사만 확인하므로 본인 인증이 약합니다. 공개 데모 전에 이 경로를 차단하거나 본인 확인을 보완해야 합니다. 사용자 단건 조회도 공개되어 있으므로 별도 개인정보 접근 제한이 필요합니다. 이번 테스트 페이지 제거만으로 전체 공개 서비스의 보안이 완성되는 것은 아닙니다.

## DB에서 직접 변경해야 할 때의 안전한 절차

UI로 변경할 수 없다면 별도 승인 후 로컬 관리자 도구를 사용하세요. 다음은 절차 설명이며 실행 코드나 DB 변경은 이번 작업에 포함하지 않았습니다.

1. 대상 계정을 소유자에게 확인하고 기존 DB를 보호된 위치에 백업합니다.
2. Java Console.readPassword 또는 PowerShell Get-Credential 같은 보안 입력으로 새 비밀번호를 받습니다. 명령 인자나 환경변수 목록에 새 비밀번호를 적지 않습니다.
3. 프로젝트와 동일한 BCryptPasswordEncoder.encode로 해시를 생성합니다. 원문과 해시는 화면에 출력하지 않습니다.
4. JDBC PreparedStatement를 사용하는 관리 도구에서 트랜잭션을 시작합니다. 대상 사용자 ID로 정확히 1행을 선택하고, UPDATE users SET password = ? WHERE id = ? 로 해시만 바인딩합니다.
5. 영향받은 행이 정확히 1개인지 검사하고, PasswordEncoder.matches로 새 값의 일치를 메모리에서 확인합니다. 결과는 성공/실패만 표시합니다.
6. 성공할 때만 커밋하고 예외 시 롤백합니다. SQL 바인딩 로깅을 켜지 않으며 비밀번호를 명령행·임시 SQL 파일·작업 기록에 남기지 않습니다.

MySQL SHA2/MD5/PASSWORD 함수는 이 로그인 구현의 BCrypt와 호환되지 않으므로 대체하지 마세요.

## 기존 세션 무효화

비밀번호 변경은 기존 HttpSession을 자동 만료시키지 않습니다. 현재 세션과 STOMP 구독 상태는 애플리케이션 메모리에 있습니다.

- 로컬: 실행 터미널에서 Ctrl+C로 종료한 뒤 새 백엔드를 시작합니다. 모든 사용자가 다시 로그인해야 합니다.
- 배포: 수정된 빌드로 모든 인스턴스를 재시작/재배포합니다. 구 버전 인스턴스가 계속 요청을 받지 않도록 합니다.
- 재시작 후 다른 브라우저 프로필의 기존 로그인으로 /users/me가 401을 반환하고 채팅이 재로그인을 요구하는지 확인합니다.
- 나중에 Redis/JDBC 세션 저장이나 재시작 시 세션 복원을 도입하면 재시작만으로는 충분하지 않습니다. 해당 세션 저장소에서도 대상 세션을 만료시켜야 합니다.
- Web Push 구독은 DB에 별도로 저장되므로 세션 만료와 다릅니다. 계정 탈취가 의심되면 소유자 확인 후 의심 기기의 구독도 별도로 철회해야 합니다. 이번 작업은 구독 데이터를 변경하지 않습니다.

## 과거 Git 기록

비밀번호 변경으로 기존 값을 먼저 무효화하세요. 같은 값을 다른 계정에서 재사용했다면 해당 계정도 변경해야 합니다. 현재 파일을 제거해도 과거 커밋과 기존 배포본/복제본에는 남을 수 있습니다.

이번 작업에서는 커밋, 푸시, 과거 이력 재작성, 강제 푸시를 하지 않습니다. 폐기된 비밀번호가 더 이상 유효하지 않은지 확인한 뒤 이력을 유지할지, 팀원 합의와 별도 승인 후 git-filter-repo로 정리할지 결정하세요. 이력 재작성은 커밋 해시와 졸업작품 증빙에 영향을 주며 포크·복제본까지 자동으로 지우지 않습니다.

## 검증

백엔드 테스트는 H2 메모리 DB만 사용합니다. 실제 계정의 비밀번호 변경 및 세션 무효화 작업은 사용자가 별도로 수행해야 합니다.
