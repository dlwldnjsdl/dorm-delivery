# Web Push 구현 계획 및 진행 기록

승인된 설계: HttpSession 인증, VAPID Web Push, MySQL 구독 저장, 채팅 본문 숨김, 현재 브라우저 로그아웃 시 구독 해제.

기존 변경: 미추적 Microsoft/ 보존. feature/web-push 브랜치에서 작업.
기준 검증: 백엔드 compile 성공, 프론트엔드 build 성공(기존 HTML 중복 선언 경고).

1. 구독 API / Service Worker / 버튼 구현 및 테스트.
2. 세션 인증과 방 권한 보완, 참여 / 채팅 / 주문 이벤트 연결 및 테스트.
3. 전체 빌드, 회귀 테스트, 실행 안내 및 보안 검토.

1단계 완료: 구독 저장/해제, Service Worker, 알림 버튼. H2 테스트와 프론트엔드 빌드 검증.
2단계 완료: 방 참여/채팅/주문 커밋 후 이벤트, 실패 격리, 세션 인증, 방 권한 확인.
보안 검토 수정: HttpOnly 기기 토큰으로 세션 만료 후 로그아웃 정리, 계정 전환 시 기존 기기 연결 해제, WebSocket 송신/수신 모두 참여 권한 검증.
빌드 문제 수정: Java 파일을 선언된 패키지 위치로 이동. 기존 dist는 .dist-before-web-push에 보존 후 빌드 성공. 진단용 소스는 제거.
검증 완료: 백엔드 17개 테스트(실패 0)와 package 통과, 프론트엔드 4개 테스트(실패 0) 통과. emptyOutDir=false 설정 후 기본 프론트엔드 빌드 연속 2회 통과. lint 종료코드 0, 기존 App.jsx 패턴 관련 경고 8개 유지. Node/PowerShell 실행 스크립트 문법 확인. 실제 구독 JSON/Origin 및 HttpOnly 기기 쿠키 검증 통과.
남은 수동 확인: 실제 브라우저의 외부 Push 서비스 수신, Windows 알림 표시. 키 생성과 실제 MySQL 서버 시작은 사용자 실행 안내에 포함.
적용한 판단: 기존 폴더에서 feature 브랜치로 작업(사용자 요청), 영속 재시도 큐는 이번 범위에 포함하지 않음. 실제 브라우저 수신은 수동 절차로 검증 필요.

기존 MySQL에 테스트를 실행하지 않음. H2 테스트 프로필 사용. 키나 비밀번호를 출력하거나 저장소에 추가하지 않음.

## 2026-11-15 VAPID 초기화 경고 수정

- 기존 키 파일: P-256 공개키 65바이트/개인키 32바이트, 키 쌍 일치, Java 라이브러리 직접 초기화 성공. 키 재생성 또는 변경 없음.
- 기존 코드의 일반 이메일 및 앞뒤 공백 거부를 실패 테스트로 재현. 포괄적 catch가 예외를 버려 과거 실행의 실제 원인은 소급 확정 불가.
- 연락처/공백 정규화, 고정 원인 코드, 키 쌍 검증, 안전한 초기화 성공 로그 추가.
- 실행 스크립트에 -Subject 및 -CheckOnly 추가. Node 자식 프로세스에서 파일/환경변수 일치 확인. 개인정보 값은 출력하지 않음.
- 백엔드 테스트 22개(브라우저 공개키 정규화 포함), 스크립트 테스트 4개, package 검증.
- 실제 기존 키 + 진단용 유효 연락처로 격리 H2/임시 포트 백엔드 시작 및 READY 확인. 기존 8080 프로세스 유지. MySQL 연결 없음. 키 파일 해시 불변 확인.
